## 서론: 오늘 해결할 문제

저장소에서 비밀 문자열을 지웠어도 이미 복사된 키는 계속 사용될 수 있다.

비밀은 값 자체보다 발급·전달·교체·폐기 과정에서 관리해야 한다. 정상 교체와 유출 대응이 같은 관측 가능한 경로를 사용하게 만든다.

## 1. 먼저 정할 모델과 계약

노출 제거와 credential 무효화는 다른 조치다. 현재 권한과 사용 흔적을 먼저 파악한다.

## 2. 설계와 구현의 경계

유출 값 폐기·교체, 영향 범위 조사, 로그 보존과 노출 경로 수정을 준비된 절차로 실행한다.

## 3. 작은 예제로 확인하기

아래 예제는 핵심 동작을 설명하기 위한 발췌다. 실제 적용 시에는 프로젝트의 타입, 권한, 의존성 버전에 맞춰 완성해야 한다.

```text
유출 탐지
  → 권한·소비자 범위 확인
  → 무효화와 대체 자격 증명 전환
  → 접근 기록 조사
  → 노출 경로 수정·재발 검증
```

훈련용 키로 탐지부터 폐기와 서비스 회복까지 걸리는 시간을 측정한다.

## 4. 자주 실패하는 방식

원인 조사 중 실제 비밀을 티켓과 채팅에 다시 복사하지 않는다.

정상 경로를 확인한 다음 이 실패 조건을 별도 사례로 재현한다. 실패 시 데이터가 어떻게 남는지와 재실행 결과까지 확인해야 복구 절차를 정할 수 있다.

## 5. 관측과 검증

탐지·폐기·전환 시간, 비정상 사용과 재노출을 본다.

측정 범위와 비교 조건을 고정한다. 같은 입력과 부하에서 변경 전후를 비교하고, 통과 기준을 배포 전에 기록한다.

## 적용 순서

```text
업무 입력과 기대 결과 정의
  → 모델·경계 구현
  → 예제와 실패 조건 재현
  → 관측 결과 비교
  → 운영 절차에 반영
```

## 실전 체크리스트

- [ ] 오늘의 문제에 대한 기대 결과를 테스트로 표현했다.
- [ ] 모델의 책임과 외부 의존성의 경계를 구분했다.
- [ ] 예제의 정상·경계·실패 입력을 각각 실행했다.
- [ ] 실패 후 재실행과 복구 결과를 확인했다.
- [ ] 핵심 지표와 변경 전후 비교 결과를 남겼다.
