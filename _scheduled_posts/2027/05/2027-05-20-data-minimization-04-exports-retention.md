## 서론: 오늘 해결할 문제

DB 접근은 통제하지만 CSV 다운로드 파일이 오래 남으면 같은 데이터가 밖에서 계속 복제된다.

데이터를 수집한 순간부터 저장·로그·분석·삭제 경로까지 추적한다. 특정 법률 해석이 아니라 불필요한 노출을 줄이는 소프트웨어 설계에 집중한다.

## 1. 먼저 정할 모델과 계약

export는 별도의 데이터 제품이며 권한, 보존 기간과 재다운로드 정책이 필요하다.

## 2. 설계와 구현의 경계

필수 열과 행 범위를 제한하고 만료되는 객체·다운로드 권한을 발급한다.

## 3. 작은 예제로 확인하기

아래 예제는 핵심 동작을 설명하기 위한 발췌다. 실제 적용 시에는 프로젝트의 타입, 권한, 의존성 버전에 맞춰 완성해야 한다.

```text
요청: 허용 열·대상 범위 확인
생성: 전용 임시 저장소
제공: 짧은 다운로드 권한
만료: 접근 차단·객체 정리
감사: 요청자·범위·완료 시각
```

대상 범위 변경, 만료 후 접근과 export worker 실패 시 임시 파일 정리를 시험한다.

## 4. 자주 실패하는 방식

스프레드시트에서 수식으로 해석될 문자열은 CSV 출력 맥락에 맞게 안전하게 처리해야 한다.

정상 경로를 확인한 다음 이 실패 조건을 별도 사례로 재현한다. 실패 시 데이터가 어떻게 남는지와 재실행 결과까지 확인해야 복구 절차를 정할 수 있다.

## 5. 관측과 검증

파일 보존 기한, 다운로드 감사, 고아 export와 열 범위 위반을 본다.

측정 범위와 비교 조건을 고정한다. 같은 입력과 부하에서 변경 전후를 비교하고, 통과 기준을 배포 전에 기록한다.

## 적용 순서

```text
업무 입력과 기대 결과 정의
  → 모델·경계 구현
  → 예제와 실패 조건 재현
  → 관측 결과 비교
  → 운영 절차에 반영
```

## 실전 체크리스트

- [ ] 오늘의 문제에 대한 기대 결과를 테스트로 표현했다.
- [ ] 모델의 책임과 외부 의존성의 경계를 구분했다.
- [ ] 예제의 정상·경계·실패 입력을 각각 실행했다.
- [ ] 실패 후 재실행과 복구 결과를 확인했다.
- [ ] 핵심 지표와 변경 전후 비교 결과를 남겼다.
