## 서론: 오늘 해결할 문제

최초 연결에서만 인증하면 권한이 회수된 사용자가 계속 이벤트를 받을 수 있다.

알림과 진행 상태 전송은 연결 유지보다 재접속·권한·과부하 처리가 어렵다. 연결과 업무 이벤트의 수명을 분리한다.

## 1. 먼저 정할 모델과 계약

연결 인증, 구독 대상 인가와 메시지별 권한은 별도 검사다. Origin 검증도 인증을 대체하지 않는다.

## 2. 설계와 구현의 경계

서버가 신뢰한 tenant·user로 구독 범위를 만들고 권한 변경 시 연결 종료 또는 재검증을 수행한다.

## 3. 작은 예제로 확인하기

아래 예제는 핵심 동작을 설명하기 위한 발췌다. 실제 적용 시에는 프로젝트의 타입, 권한, 의존성 버전에 맞춰 완성해야 한다.

```text
연결 인증
  → Origin·환경 정책 확인
  → 대상 job의 소유권 검사
  → 구독 생성
권한 회수·만료 → 구독 종료 또는 재검증
```

다른 사용자의 job ID 구독, 만료된 세션과 허용되지 않은 Origin을 시험한다.

## 4. 자주 실패하는 방식

URL query에 긴 수명 토큰을 넣으면 proxy와 접근 로그에 남을 수 있다.

정상 경로를 확인한 다음 이 실패 조건을 별도 사례로 재현한다. 실패 시 데이터가 어떻게 남는지와 재실행 결과까지 확인해야 복구 절차를 정할 수 있다.

## 5. 관측과 검증

무단 구독 거절, 만료 후 연결과 민감 토큰 로그를 확인한다.

측정 범위와 비교 조건을 고정한다. 같은 입력과 부하에서 변경 전후를 비교하고, 통과 기준을 배포 전에 기록한다.

## 적용 순서

```text
업무 입력과 기대 결과 정의
  → 모델·경계 구현
  → 예제와 실패 조건 재현
  → 관측 결과 비교
  → 운영 절차에 반영
```

## 실전 체크리스트

- [ ] 오늘의 문제에 대한 기대 결과를 테스트로 표현했다.

- [ ] 예제의 정상·경계·실패 입력을 각각 실행했다.
- [ ] 실패 후 재실행과 복구 결과를 확인했다.
- [ ] 핵심 지표와 변경 전후 비교 결과를 남겼다.
