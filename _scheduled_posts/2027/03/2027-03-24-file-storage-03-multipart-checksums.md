## 서론: 오늘 해결할 문제

네트워크가 끊긴 대형 파일을 처음부터 다시 보내면 시간과 비용이 커진다.

파일 바이트와 업무 상태를 분리하고 업로드·검증·공개·삭제의 수명주기를 관리한다. 객체 저장소를 사용해도 권한과 정합성 책임은 남는다.

## 1. 먼저 정할 모델과 계약

multipart는 부분 단위 재전송을 가능하게 하지만 미완료 조각과 완료 처리를 관리해야 한다.

## 2. 설계와 구현의 경계

upload ID와 part 정보를 기록하고 완료·중단을 멱등하게 처리한다. 파일 무결성은 지원 checksum으로 검증한다.

## 3. 작은 예제로 확인하기

아래 예제는 핵심 동작을 설명하기 위한 발췌다. 실제 적용 시에는 프로젝트의 타입, 권한, 의존성 버전에 맞춰 완성해야 한다.

```text
INIT → uploadId
PART 1..N → part 번호·검증 정보 기록
RETRY → 실패한 part만 전송
COMPLETE → 최종 checksum·크기 확인
ABORT → 미완료 업로드 정리
```

일부 part만 성공한 뒤 재접속하고 완료 요청을 반복해 최종 파일을 비교한다.

## 4. 자주 실패하는 방식

multipart ETag를 파일 전체의 단순 MD5라고 가정하면 무결성 판단이 틀릴 수 있다.

정상 경로를 확인한 다음 이 실패 조건을 별도 사례로 재현한다. 실패 시 데이터가 어떻게 남는지와 재실행 결과까지 확인해야 복구 절차를 정할 수 있다.

## 5. 관측과 검증

재전송 바이트, 미완료 업로드 나이, checksum 실패와 정리 비용을 본다.

측정 범위와 비교 조건을 고정한다. 같은 입력과 부하에서 변경 전후를 비교하고, 통과 기준을 배포 전에 기록한다.

## 적용 순서

```text
업무 입력과 기대 결과 정의
  → 모델·경계 구현
  → 예제와 실패 조건 재현
  → 관측 결과 비교
  → 운영 절차에 반영
```
