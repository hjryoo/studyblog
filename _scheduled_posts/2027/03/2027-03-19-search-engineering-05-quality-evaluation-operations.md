## 서론: 오늘 해결할 문제

응답 시간이 줄어도 사용자가 찾는 문서가 아래로 밀리면 검색 품질은 나빠진다.

검색 결과는 DB 원본, 색인 지연, 분석기와 질의가 결합된 산출물이다. 사용자의 검색 의도와 운영 비용을 함께 검증한다.

## 1. 먼저 정할 모델과 계약

관련성 평가는 대표 질의와 사람이 판단한 기대 문서를 기준으로 한다.

## 2. 설계와 구현의 경계

오타·희소 질의·인기 질의 집합을 만들고 관련성 지표와 latency를 함께 비교한다.

## 3. 작은 예제로 확인하기

아래 예제는 핵심 동작을 설명하기 위한 발췌다. 실제 적용 시에는 프로젝트의 타입, 권한, 의존성 버전에 맞춰 완성해야 한다.

```text
평가 질의: 상품 코드 / 일반 검색 / 오타
기대 문서: 도메인 전문가가 검토
비교: 상위 K 관련성 + 지연
운영: 질의 그룹별 회귀 확인
배포: 점진 노출과 되돌림
```

분석기나 boost를 바꾼 후보를 같은 평가 집합으로 재실행한다.

## 4. 자주 실패하는 방식

클릭 수만 최적화하면 노출 위치와 인기 편향을 관련성으로 오해할 수 있다.

정상 경로를 확인한 다음 이 실패 조건을 별도 사례로 재현한다. 실패 시 데이터가 어떻게 남는지와 재실행 결과까지 확인해야 복구 절차를 정할 수 있다.

## 5. 관측과 검증

상위 K 적합도, 무결과율, p95 지연과 timeout을 동시에 본다.

측정 범위와 비교 조건을 고정한다. 같은 입력과 부하에서 변경 전후를 비교하고, 통과 기준을 배포 전에 기록한다.

## 적용 순서

```text
업무 입력과 기대 결과 정의
  → 모델·경계 구현
  → 예제와 실패 조건 재현
  → 관측 결과 비교
  → 운영 절차에 반영
```

## 실전 체크리스트

- [ ] 오늘의 문제에 대한 기대 결과를 테스트로 표현했다.
- [ ] 모델의 책임과 외부 의존성의 경계를 구분했다.
- [ ] 예제의 정상·경계·실패 입력을 각각 실행했다.
- [ ] 실패 후 재실행과 복구 결과를 확인했다.
- [ ] 핵심 지표와 변경 전후 비교 결과를 남겼다.
