## 서론: 오늘 해결할 문제

중복 제거를 위해 Set으로 바꿨는데 화면 순서와 집계 건수가 달라질 수 있다.

컬렉션 선택은 속도뿐 아니라 순서, 중복, 동등성, 변경 권한을 결정한다. 주문 항목과 집계 예제로 숨은 계약을 검증한다.

## 1. 먼저 정할 모델과 계약

List는 순서와 중복을, Set은 동등성에 따른 유일성을, Map은 키와 값의 연결을 표현한다. 원하는 불변 조건에서 선택을 시작한다.

## 2. 설계와 구현의 경계

조회 방식과 순서 보존 요구를 먼저 적는다. 중복이 오류인지 병합 가능한 사건인지 구분해 데이터 손실을 막는다.

## 3. 작은 예제로 확인하기

아래 예제는 핵심 동작을 설명하기 위한 발췌다. 실제 적용 시에는 프로젝트의 타입, 권한, 의존성 버전에 맞춰 완성해야 한다.

```java
List<String> input = List.of("B", "A", "B");
Set<String> unique = new LinkedHashSet<>(input);
// 최초 등장 순서: B, A
Map<String, Long> counts = input.stream().collect(
    Collectors.groupingBy(Function.identity(), Collectors.counting()));
```

같은 주문 ID가 두 번 온 입력으로 보존·거절·병합 결과를 비교한다.

## 4. 자주 실패하는 방식

중복을 조용히 없애면 생산자 재전송과 실제 중복 주문의 차이를 잃는다.

정상 경로를 확인한 다음 이 실패 조건을 별도 사례로 재현한다. 실패 시 데이터가 어떻게 남는지와 재실행 결과까지 확인해야 복구 절차를 정할 수 있다.

## 5. 관측과 검증

입력 건수, 중복 건수, 출력 건수와 정렬 계약을 함께 검증한다.

측정 범위와 비교 조건을 고정한다. 같은 입력과 부하에서 변경 전후를 비교하고, 통과 기준을 배포 전에 기록한다.

## 적용 순서

```text
업무 입력과 기대 결과 정의
  → 모델·경계 구현
  → 예제와 실패 조건 재현
  → 관측 결과 비교
  → 운영 절차에 반영
```
