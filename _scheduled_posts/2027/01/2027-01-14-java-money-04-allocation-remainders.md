## 서론: 오늘 해결할 문제

1원을 여러 주문 항목에 비례 배분하면 반올림 때문에 총액이 달라질 수 있다.

주문 금액은 계산 가능성뿐 아니라 통화, 반올림 시점, 재현 가능한 정산 규칙을 가져야 한다. 단위와 정책을 코드 경계에 드러낸다.

## 1. 먼저 정할 모델과 계약

배분 알고리즘은 각 항목의 정확성뿐 아니라 배분액 합계가 원금과 같다는 불변 조건을 지켜야 한다.

## 2. 설계와 구현의 경계

최소 통화 단위의 정수로 기본 몫을 계산하고 남은 단위를 명시된 순서로 배정한다. 동률에는 안정적인 ID 순서를 사용한다.

## 3. 작은 예제로 확인하기

아래 예제는 핵심 동작을 설명하기 위한 발췌다. 실제 적용 시에는 프로젝트의 타입, 권한, 의존성 버전에 맞춰 완성해야 한다.

```text
배분 원금: 100원
동일 가중치 항목: A, B, C
기본 몫: 33, 33, 33
남은 단위: 1
동률 규칙 A 우선 → 34, 33, 33
검증: sum(allocations) = 100
```

세 항목에 100원을 나눌 때 33·33·34 같은 결과와 합계를 확인한다. 입력 순서가 바뀌어도 정책대로 재현돼야 한다.

## 4. 자주 실패하는 방식

마지막 항목에 무조건 차액을 주면 음수·0원 항목이나 정렬 변경에 따라 결과가 불공정해질 수 있다.

정상 경로를 확인한 다음 이 실패 조건을 별도 사례로 재현한다. 실패 시 데이터가 어떻게 남는지와 재실행 결과까지 확인해야 복구 절차를 정할 수 있다.

## 5. 관측과 검증

배분 전후 총액 차이와 음수 항목, 재실행 결과 차이를 검사한다.

측정 범위와 비교 조건을 고정한다. 같은 입력과 부하에서 변경 전후를 비교하고, 통과 기준을 배포 전에 기록한다.

## 적용 순서

```text
업무 입력과 기대 결과 정의
  → 모델·경계 구현
  → 예제와 실패 조건 재현
  → 관측 결과 비교
  → 운영 절차에 반영
```

## 실전 체크리스트

- [ ] 실패 후 재실행과 복구 결과를 확인했다.
- [ ] 핵심 지표와 변경 전후 비교 결과를 남겼다.
