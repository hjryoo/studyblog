## 서론: 오늘 해결할 문제

현재 시간을 직접 조회하는 테스트는 자정이나 실행 속도에 따라 간헐적으로 실패한다.

예약·정산 서비스에서는 같은 시각을 저장하고 다시 읽어도 업무상 의미가 보존돼야 한다. 시간 표현, 경계, 테스트를 하나의 계약으로 다룬다.

## 1. 먼저 정할 모델과 계약

Clock은 현재 시각을 공급하는 의존성이다. 업무 코드가 시계를 주입받으면 시간 흐름과 정책 판단을 분리할 수 있다.

## 2. 설계와 구현의 경계

요청 시작 시 기준 Instant를 한 번 읽고 관련 판단에 재사용한다. 저장 시간과 만료 비교가 서로 다른 now를 읽지 않게 한다.

## 3. 작은 예제로 확인하기

아래 예제는 핵심 동작을 설명하기 위한 발췌다. 실제 적용 시에는 프로젝트의 타입, 권한, 의존성 버전에 맞춰 완성해야 한다.

```java
Clock clock = Clock.fixed(
    Instant.parse("2027-01-05T00:00:00Z"), ZoneOffset.UTC);
Instant expiresAt = clock.instant().plusSeconds(60);
boolean expired = !clock.instant().isBefore(expiresAt);
```

만료 직전·정각·직후의 시계를 고정해 경계 조건을 검증한다. 테스트에서 Thread.sleep으로 시간을 보내지 않는다.

## 4. 자주 실패하는 방식

static now 호출이 일부 남아 있으면 고정 Clock을 사용해도 결과가 흔들린다.

정상 경로를 확인한 다음 이 실패 조건을 별도 사례로 재현한다. 실패 시 데이터가 어떻게 남는지와 재실행 결과까지 확인해야 복구 절차를 정할 수 있다.

## 5. 관측과 검증

시간 관련 테스트의 반복 실패율과 직접 now 호출을 점검한다. 만료 비교의 포함·제외 조건도 검사한다.

측정 범위와 비교 조건을 고정한다. 같은 입력과 부하에서 변경 전후를 비교하고, 통과 기준을 배포 전에 기록한다.

## 적용 순서

```text
업무 입력과 기대 결과 정의
  → 모델·경계 구현
  → 예제와 실패 조건 재현
  → 관측 결과 비교
  → 운영 절차에 반영
```
