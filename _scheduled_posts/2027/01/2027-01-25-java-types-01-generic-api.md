## 서론: 오늘 해결할 문제

Object를 반환하는 공통 유틸은 호출부마다 캐스팅과 런타임 오류를 만든다.

잘못된 상태와 변환을 컴파일 단계에서 줄이면 검증 코드와 운영 예외가 줄어든다. 공개 API와 도메인 경계에 타입 정보를 남긴다.

## 1. 먼저 정할 모델과 계약

타입 매개변수는 입력과 출력 사이의 관계를 표현한다. 의미가 다른 값을 한 T로 묶는다고 업무 관계가 생기지는 않는다.

## 2. 설계와 구현의 경계

호출자가 알아야 하는 타입 관계만 공개하고 내부 구현 타입은 숨긴다. raw type은 경고를 방치하지 않고 경계에서 제거한다.

## 3. 작은 예제로 확인하기

아래 예제는 핵심 동작을 설명하기 위한 발췌다. 실제 적용 시에는 프로젝트의 타입, 권한, 의존성 버전에 맞춰 완성해야 한다.

```java
static <T> T first(List<T> values) {
  if (values.isEmpty()) throw new IllegalArgumentException("empty");
  return values.get(0);
}
String value = first(List.of("A", "B"));
```

동일 타입의 요소를 선택하는 함수와 서로 다른 타입을 변환하는 함수를 분리한다.

## 4. 자주 실패하는 방식

편의를 위해 모든 경고를 suppress하면 잘못된 캐스팅이 멀리 떨어진 위치에서 터진다.

정상 경로를 확인한 다음 이 실패 조건을 별도 사례로 재현한다. 실패 시 데이터가 어떻게 남는지와 재실행 결과까지 확인해야 복구 절차를 정할 수 있다.

## 5. 관측과 검증

unchecked 경고와 ClassCastException을 추적하고 공개 시그니처를 리뷰한다.

측정 범위와 비교 조건을 고정한다. 같은 입력과 부하에서 변경 전후를 비교하고, 통과 기준을 배포 전에 기록한다.

## 적용 순서

```text
업무 입력과 기대 결과 정의
  → 모델·경계 구현
  → 예제와 실패 조건 재현
  → 관측 결과 비교
  → 운영 절차에 반영
```
