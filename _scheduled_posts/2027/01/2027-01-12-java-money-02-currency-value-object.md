## 서론: 오늘 해결할 문제

100이라는 숫자만 전달하면 원화인지 달러인지, 최소 단위인지 알 수 없다.

주문 금액은 계산 가능성뿐 아니라 통화, 반올림 시점, 재현 가능한 정산 규칙을 가져야 한다. 단위와 정책을 코드 경계에 드러낸다.

## 1. 먼저 정할 모델과 계약

Money는 금액과 통화를 묶은 값이다. 서로 다른 통화의 덧셈은 환율 변환과 별개의 명시적 작업이어야 한다.

## 2. 설계와 구현의 경계

생성 시 null과 허용 단위를 검사하고 연산 결과도 같은 불변 타입으로 반환한다. 수량·비율·금액은 서로 다른 타입으로 구분한다.

## 3. 작은 예제로 확인하기

아래 예제는 핵심 동작을 설명하기 위한 발췌다. 실제 적용 시에는 프로젝트의 타입, 권한, 의존성 버전에 맞춰 완성해야 한다.

```java
record Money(BigDecimal amount, Currency currency) {
  Money add(Money other) {
    if (!currency.equals(other.currency))
      throw new IllegalArgumentException("currency mismatch");
    return new Money(amount.add(other.amount), currency);
  }
}
```

USD와 KRW를 더하는 경로가 거절되는지 테스트한다. 환율에는 기준 시각과 제공자를 붙인다.

## 4. 자주 실패하는 방식

통화 문자열만 비교하고 환율 기준을 버리면 과거 정산을 재현할 수 없다.

정상 경로를 확인한 다음 이 실패 조건을 별도 사례로 재현한다. 실패 시 데이터가 어떻게 남는지와 재실행 결과까지 확인해야 복구 절차를 정할 수 있다.

## 5. 관측과 검증

통화 불일치, 암묵적 변환, 허용 소수점 위반을 검증한다.

측정 범위와 비교 조건을 고정한다. 같은 입력과 부하에서 변경 전후를 비교하고, 통과 기준을 배포 전에 기록한다.
