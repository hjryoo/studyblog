## 서론: 오늘 해결할 문제

프로세스가 재시작되면 어느 외부 단계까지 끝났는지 알 수 없는 업무가 있다.

여러 서비스에 걸친 업무를 재시작 가능한 상태 전이로 모델링한다. 프로세스 메모리와 실제 업무 진행 상태를 분리한다.

## 1. 먼저 정할 모델과 계약

진행 상태와 허용 전이는 업무 계약이다. 상태 이름뿐 아니라 명령과 결과 이력을 보존한다.

## 2. 설계와 구현의 경계

workflow ID와 step ID를 안정되게 만들고 상태 전이를 조건부 갱신한다.

## 3. 작은 예제로 확인하기

아래 예제는 핵심 동작을 설명하기 위한 발췌다. 실제 적용 시에는 프로젝트의 타입, 권한, 의존성 버전에 맞춰 완성해야 한다.

```text
CREATED → INVENTORY_RESERVED → PAYMENT_APPROVED
  → COMPLETED
실패 경로: COMPENSATING → CANCELLED
각 전이: workflowId·이전 상태·결과 저장
```

각 단계 직후 프로세스를 종료한 뒤 저장 상태만으로 다음 행동을 결정한다.

## 4. 자주 실패하는 방식

메모리 플래그와 로그 문장만으로 진행을 판단하면 자동 복구가 어렵다.

정상 경로를 확인한 다음 이 실패 조건을 별도 사례로 재현한다. 실패 시 데이터가 어떻게 남는지와 재실행 결과까지 확인해야 복구 절차를 정할 수 있다.

## 5. 관측과 검증

상태별 체류 시간, 잘못된 전이와 재시작 후 미결 업무를 본다.

측정 범위와 비교 조건을 고정한다. 같은 입력과 부하에서 변경 전후를 비교하고, 통과 기준을 배포 전에 기록한다.

## 적용 순서

```text
업무 입력과 기대 결과 정의
  → 모델·경계 구현
  → 예제와 실패 조건 재현
  → 관측 결과 비교
  → 운영 절차에 반영
```

## 실전 체크리스트

- [ ] 오늘의 문제에 대한 기대 결과를 테스트로 표현했다.
- [ ] 모델의 책임과 외부 의존성의 경계를 구분했다.
- [ ] 예제의 정상·경계·실패 입력을 각각 실행했다.
- [ ] 실패 후 재실행과 복구 결과를 확인했다.
- [ ] 핵심 지표와 변경 전후 비교 결과를 남겼다.
